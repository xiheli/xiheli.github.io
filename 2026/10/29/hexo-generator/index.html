Hexo 生成器：一篇文章是怎么变成页面的

读 hexo-generator-index、category、tag、archive 之后发现，所谓「生成页面」不过是返回 path + layout + data 三个字段，剩下的交给路由。

2026-10-29 · 周四 · 约 1 分钟 · 351 字

一直在用 Hexo，但没认真看过它的生成器。今天把 hexo-generator-index、hexo-generator-category、hexo-generator-tag、hexo-generator-archive 四个包的源码读了一遍。

生成器的真身

一个生成器就是一个注册在 hexo.extend.generator 上的函数，接收 locals，返回一个（或一组）对象：

真正把它写成 HTML 的是路由：Hexo 遍历 layout 数组，找到主题里第一个存在的视图，然后用 data 渲染。所以主题只需要保证 index.ejs 存在，没人用到的布局会被自动跳过。

值得记下来的几个细节

  1. layout 是数组，不是字符串。 ['category', 'archive', 'index'] 表示「分类页优先，没有就退化成归档页，再没有就用首页模板」。自己写主题时可以利用这个降级顺序。
  2. 分页统一由 hexo-pagination 处理。 传 perPage: 0 时 total 是 1 且不分片，所以「关闭分页」不是特判，而是分页函数的自然结果。
  3. 分类和标签索引页不会自动生成。 分类生成器只为每个分类生成页面，/categories/ 这个汇总页需要自己在 source/ 里建一个 page。
  4. page.layout 拿到的是生成器给的数组。 主题里判断页面类型时用 is_home() / is_post() 这类 helper，比直接读 page.layout 稳。

顺带一提

locals.posts 是 Warehouse 的 Query，.sort()、.filter() 都是惰性的；.toArray() 之后才是普通数组。在模板里写 site.posts.toArray() 记得只调用一次。
