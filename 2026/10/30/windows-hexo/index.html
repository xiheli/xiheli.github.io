Windows 上跑 Hexo 遇到的三个小问题

npm.ps1 被安全策略挡住、时区拼错导致日期错乱、分页关不掉。三个都是小问题，但每个都能让人卡十分钟。

2026-10-30 · 周五 · 约 1 分钟 · 390 字

在 Windows 上重新初始化博客时踩了三个坑，记一下，省得下次再查。

一、npm : 无法加载文件 npm.ps1

PowerShell 默认的执行策略会禁止运行 .ps1 脚本，于是 npm、npx 全都报错：

两种解法，任选其一：

  • 临时用 npm.cmd / npx.cmd 代替，最省事；
  • 或者给当前用户放开执行策略：

二、时区写错，日期整体偏移

_config.yml 里时区是 Asia/Shanghai，我手滑写成了 Asiz/Shanghai。Hexo 不会报错，只会默默按无效时区处理，于是所有文章的日期都对不上。

排查方法：随便打开一篇生成后的页面，看 <time> 里的时间和文章 date 是否一致。如果差了几个小时，先怀疑时区。

结论：拼错的配置不会报错，只会让结果静默变错。 改完配置最好重新 hexo clean && hexo g 再看一眼。

三、per_page: 0 不只是「不分页」

我原以为 per_page: 0 表示「用默认值」，实际上是「不做分片」。分页函数会把所有文章放进同一页，total 恒为 1。

这对日志站是好事：首页拿到全量数据，筛选、搜索都能在前端做，不用考虑第二页。代价是文章多了以后首屏会变重，所以记录超过几百篇时记得改回一个具体数字。

小结

Windows + Hexo 的组合本身没问题，问题多半藏在「配置拼写」和「执行策略」这两类地方。遇到莫名其妙的报错，先怀疑环境，再怀疑代码。
