使用说明：怎么写、怎么改、怎么发布

从文档格式、分类标签，到页面布局、主题修改和部署上线，这个站的使用说明都在这篇里。

2026-11-08 · 周日 · 约 4 分钟 · 1424 字

这篇是给自己（和偶尔来帮忙的朋友）看的操作手册：怎么加一条记录、分类怎么分、页面和主题怎么改、最后怎么发布出去。

一分钟上手

站点结构：

支持哪些文档格式

文章主体是 Markdown（.md），一篇一个文件，放在 source/_posts/ 下。

正文里可以直接用：

  • 标题、列表、表格、引用、分割线
  • 行内代码和代码块（带语法高亮、可一键复制）
  • 图片：png / jpg / jpeg / gif / webp / svg
  • 普通链接、锚点链接
  • 少量 HTML，比如 <details> 折叠块、<audio>、<video>

不支持的情况：

  • Word / PDF 不能直接当文章。要么转成 Markdown，要么把文件放进 source/ 当作附件，用链接指向它。
  • 数学公式、流程图（Mermaid）默认没有开启，需要额外装 Hexo 插件；需要的话再说。
  • 视频不建议直接放进仓库，用外链更省空间。

写一条记录

  1. 新建：npm run log -- "标题"，会按模板生成文件，自动填好当前时间。
  2. 填 front matter（文件开头 --- 之间的部分）。
  3. 写正文，npm run server 预览。
  4. npm run build && npm run deploy 发布。

front matter 字段：

字段 作用
title 标题
date 发布时间。这是你写的时间，不是 git 提交时间，排序、归档、首页日期都用它
categories 分类，见下一节
tags 标签，可以多个
description 卡片和搜索里的一句话摘要，可留空（留空会截取正文）
sticky 置顶权重，数字越大越靠前，比如 sticky: 100

npm run log 会把创建时的时间写进 date。之后想改时间，直接改这一行就行，不用重新提交。

几个已经实现的细节：

  • 父分类页面会包含它下面子分类的文章；子分类有独立页面。
  • 分类页顶部会列出「子分类」「同级」，可以横向切换。
  • 子分类沿用父分类的颜色，不用单独配色。
  • 首页的分类筛选按钮只显示一级分类，但筛选父分类时会把子分类文章一起筛出来。
  • 新分类不用注册，写进 front matter 就会自动生成页面；想加一句描述，在 _config.chronicle.yml 的 categories 下补一条即可。

标签怎么加

标签页（/tags/）和标签云会自动生成；卡片上最多显示 3 个。

摘要与置顶

  • description 会显示在首页卡片、搜索结果里，写一句就够。
  • 想置顶就加 sticky: 100（数字越大越靠前，不写就是普通排序）。

修改布局和主题

模板都在 themes/chronicle/layout/：

  • layout.ejs：整页外壳（头、尾、搜索框）
  • index.ejs：首页
  • post.ejs：文章页
  • category.ejs / categories.ejs：分类页与分类总览
  • archive.ejs：归档页（按年 + 月分组）
  • tag.ejs / tags.ejs：标签页
  • _partial/：头部、尾部、侧栏、日志卡片、分页、搜索等组件

样式在 themes/chronicle/source/css/style.css，颜色和字体集中在文件开头的 :root（深色模式在 [data-theme="dark"]）。改配色基本只需要动这几个变量。

交互在 themes/chronicle/source/js/app.js：分类筛选、搜索、目录、代码复制、阅读进度、深浅色切换。

几个已经有的交互，改布局时留意别破坏：

  • 首页和列表页的整张卡片都可以点击（标题链接上铺了一层透明链接；分类、标签、阅读按钮单独可点）。
  • 归档页按「年 → 月」分组，点月份可以只看那个月。
  • 分类页有子分类、同级分类的快捷入口。

部署

源码和公开页面分开放：

  • 私有仓库 xiheli/xiheli-blog：source/、themes/、配置和脚本，只有你能看。
  • 公开仓库 xiheli/xiheli.github.io：只放构建后的 HTML/CSS/JS，GitHub Pages 从 main 读页面。

发布：

deploy 会自动执行 hexo clean → hexo generate，然后把 public/ 做成一个没有父提交的单快照，强制推送到公开仓库的 main。所以公开仓库永远只有一条提交，看不到之前版本的 HTML diff。

旧提交会从分支上移除，但 GitHub 后台可能还会保留一段时间；要彻底清掉需要删库重建或联系 GitHub Support。

常见问题

  • npm 报 “无法加载文件 npm.ps1”：PowerShell 执行策略限制，用 npm.cmd 代替，或执行 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned。
  • 日期不对：检查 _config.yml 的 timezone: Asia/Shanghai，以及文章里的 date。
  • 改了没生效：npm run clean && npm run build，浏览器再强制刷新。
  • 搜索没更新：search.json 是构建时生成的，重新构建、部署即可。
  • 中文分类 URL 很长：浏览器会把中文编码成 %E9%A1%B9...，属于正常现象。
  • 想删示例文章：直接删 source/_posts/ 下对应的 .md，重新构建即可。
